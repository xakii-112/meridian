02 · Matching engine

Tens of nanoseconds per message, no allocations, same tape every time

Header-only C++20. Prices are integer ticks on a ladder indexed by tick offset; each level is an intrusive FIFO of slots in a preallocated arena; a 64-ary summary bitset finds the next non-empty level in O(log₆₄ N). Order ids carry a slot generation, so cancels are one array lookup. The engine never reads a clock, which makes it a deterministic state machine.

03 · Research

Where to quote, and what speed is worth

1 · Fill intensity calibration

Probe quotes at random depths. Fills per second of resting time fall off exponentially with distance from fair value; the fit gives the A and κ that the closed-form quotes need.

2 · Tuning on in-sample seeds

Each strategy family is tuned on its own grid using in-sample seeds only. Points trace mean versus standard deviation of hourly PnL; the ringed point is the Sharpe-maximising choice carried out of sample.

05 · Verification

Two independent implementations, one trade tape

The Python simulator records every order it sends as an MWP tape. The C++ engine replays the tape and must reproduce the same trades in the same order, folded into the same 64-bit hash. The optimized book is also fuzzed against a deliberately naive reference model after every single command.

    06 · Reproduce

    Build, test, measure

    Everything on this page is regenerated from the repository by these commands.

    # engine: build (clang++ ≥ 17 or g++ ≥ 13), test, benchmark
cmake -S engine -B engine/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build engine/build
engine/build/meridian_tests
engine/build/meridian_bench --ops 5000000 --json results/bench.json

# research: tests (includes C++ cross-check), then the full study
cd research && python -m pytest
python -m meridian_research.study --out ../results

# real data: record Binance public streams (no keys, no orders), then replay and calibrate
python -m meridian_research.binance.recorder --minutes 90 --out ../data/binance
python -m meridian_research.binance.study ../data/binance/<session> --out ../results/real

# live paper trading (virtual orders only), then an exact offline replay of the same session
python -m meridian_research.binance.paper --minutes 15 --record
python -m meridian_research.binance.paper --replay ../results/paper/<paper_session> --verify

# this page
python dashboard/build.py

    Simulation results describe a synthetic market. Fees beyond the maker rebate, queue competition from other fast market makers, hedging costs and capital charges are not modelled, so absolute PnL and Sharpe ratios are far higher than a live desk would see; the comparisons between strategies, reference prices and latencies are the result.
